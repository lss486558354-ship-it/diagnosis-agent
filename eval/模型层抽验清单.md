# 模型层抽验清单

> 针对 `diagnosis-agent` 的 MCP + RAG 服务，人工抽验模型输出真伪的协议。
> 配套：`eval/report.md` 测的是**检索层**（结果里有没有正确答案）；
> 这份清单测的是**模型层**（模型有没有照着结果如实作答）。

---

## 0. 先读这一节：怎么避免冤枉模型

抽验的第一目的是抓幻觉，但**先要防的是核验者自己出错**。

### 一个真实案例：V1 端子电压

第 3 层复测时模型说「`飞特总线舵机通讯方法.md` 要求 V1 端子接 6~9V」。
初次核验判为**编造**，理由是「全文只有 `:147` 一处提 V1，原文是『舵机动力仍接
V1 端子』，**没有任何电压值**」。这个判定**是错的**。

```
grep -n "V1" corpus/scallion/飞特总线舵机通讯方法.md
  :131  ……右侧 SCS 为三芯 G / V1 / S……
  :147  ……舵机动力仍接 V1 端子          ← 核验停在了这里
  :152  1. SCS 舵机插在 SCS 口（G、V1、S）……
  :153  2. V1 螺丝端子 按丝印接 6～9 V     ← 真正的答案，隔了 6 行
```

`:147` 那句读起来正好是"提到了 V1 但没给数值"的完美证据 —— **于是检索在那里就停了**。
模型是对的，核验是错的。

同一个人在同一份文档上还犯过一次同类错误：把 252 行的实测样本误判为编造，
实际只是读错了章节范围（当时只看了 4.3 节，样本在 5.1 节）。

### 三条硬规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **判「编造」必须给出全文检索的证据**，不能用「我没找到」代替「不存在」 | 「我没找到」和「不存在」是两回事，前者只说明检索方式有问题。上面两次误判都是这么来的 |
| 2 | **搜到第一处就继续搜完**，`grep -c` 数一下命中总数，别看到能支持结论的一句就收工 | 同一份文档里同一主题常常分散在多处（`:147` 与 `:153`） |
| 3 | **模型答错 ≠ 模型编造**。三种要分开记：<br>① 编造（文档里根本没这回事）<br>② 张冠李戴（内容真实但出处错位）<br>③ 照抄源文档的错（源头就错，模型没察觉） | 三者成因不同、修法完全不同。混成一句"幻觉"就没法改进了。<br>第 ③ 类的实例：`流程汇报_20260423.md` 原写 `0x0466 (dec=1150 = 1024+126)` 三个数互相矛盾，模型照抄还推荐用户拿它当验证基准 |

## 1. 怎么跑

1. **一题一个新会话。** 模型的跨轮记忆会污染结果 —— 上一轮的回答会被当成本轮的前提，
   分不清是"检索到的"还是"自己刚说过的"。
2. **保留工具调用日志。** 要能看到 `called equipment-diagnosis N times` 这类记录，
   判断它到底查没查库、查了几次。0 次调用还答得头头是道 = 纯凭训练数据编。
3. **逐条核验断言，不核验整体印象。** 「回答看起来挺专业」不是证据。
   把输出拆成一条条**可判真伪的硬断言**（引脚号、命令码、电压、文件名、章节号），
   再逐条 grep 语料。
4. **记下每条断言对应的语料位置**（文件:行号）。核验不了出处的断言，一律存疑。

## 2. 十道必问题

每题给出：**考察点 / 期望答案 / 编造长什么样 / 怎么核验**。
所有期望答案均已在本语料中逐条 grep 验证过。

### Q1　V1 端子接多少伏？〔校准题〕

- **考察点**：这道题是给**核验者**准备的，不是给模型的。答案确实在库里，
  但它藏在一个看起来"已经找到答案"的位置后面 6 行（见第 0 节）。
- **期望**：**6～9 V**（SCS 供电）。出处 `飞特总线舵机通讯方法.md:153`。
- **错答**：答 5V / 12V / 24V，或答「文档没写」。
- **核验**：`grep -n "V1" corpus/scallion/飞特总线舵机通讯方法.md` ——
  **必须看完所有命中行**，不能停在第一处。

### Q2　急停按钮应该是常开还是常闭？

- **考察点**：安全回路的核心概念。答反了会导致相反的维修动作。
- **期望**：**常闭**。急停串在回路上，按下时**断开**。
  出处 `继电保护设计.md:79`（「急停｜AC急停按钮｜DC急停按钮｜**常闭型**」）。
  加分：能说出「接成常开 → 按下无法断电」＝ CASE-010。
- **编造/错答**：说"常开"；或不表态（「要看具体接法」）。
- **核验**：`grep -rn "常开\|常闭" corpus/scallion/` —— 注意同一份文档里
  启动按钮是**常开**、停止按钮是**常闭**，别把三者搞混。

### Q3　「设备运行中自己断电」和「按下急停却断不了电」，原因分别是什么？〔辨别题〕

- **考察点**：**这两个案例互为镜像**，是张冠李戴的高发区。
- **期望**：
  | 症状 | 根因 | 出处 |
  |---|---|---|
  | 运行中意外断电 | 急停按钮**抖动/接触不良**，常闭触点**瞬断** | CASE-014 |
  | 按下急停无法断电 | 急停被**接成了常开型** | CASE-010 |
- **判定**：两条都对且没互换 = 满分。**互换 = 严重错误** —— 维修动作完全相反
  （一个要查接触不良，一个要改接线）。
- **核验**：`cases_seed.json` 中 CASE-010 / CASE-014 的 `cause` 字段。

### Q4　限位开关接在哪些引脚上？〔冲突题〕

- **考察点**：**语料内部本身矛盾**，看模型是"指出冲突"还是"随便挑一个说得斩钉截铁"。
- **期望**：指出两种说法并存 ——
  `固件README.md:139` 写 **PE0-PE6**；
  `外设接线表.md:168` 与 `流程汇报_20260423.md:133` 写 **PE0～PE7**（2:1）。
- **分级**：指出冲突 = 满；给 PE0~PE7 但没提冲突 = 及格（多数派）；
  斩钉截铁给 PE0-PE6 = 不及格；编出 PE8 / PA0 之类 = 编造。
- **核验**：`grep -rn "PE0" corpus/scallion/`

### Q5　超声波模块的 TRIG 和 ECHO 分别接哪？

- **考察点**：唯一答案题，看会不会编引脚。
- **期望**：**TRIG = PB0**；**ECHO1 = PD3**（大葱测高）、**ECHO2 = PD4**（打包测距）。
  两路超声波**共用同一个 TRIG**，这点容易漏。
- **编造**：给出 PA0 / PB1 / PC13 等语料里没有的引脚。
- **核验**：`grep -rn "PB0\|PD3\|PD4" corpus/scallion/`

### Q6　0x2E 寄存器写速度，字节序是高字节在前还是低字节在前？〔冲突题〕

- **考察点**：语料里 **2:1 的矛盾**，且实测数据支持的是**少数派**那一方。
- **期望**：
  - 指出三份文档说法不一：`流程汇报_20260423.md:233` 说**大端**；
    `飞特总线舵机通讯方法.md:79` 和 `串口命令汇总表.md:181` 说**小端**。
  - 加分：知道 `流程汇报` 5.1 节的实测帧数据字节是 `04 86`，
    按 `0x0486 = 1158 = 1024 + 134`（对应 `speed=-134`）反推，**支持大端**。
  - 满分还要说一句：这点**尚未定论**（技术债 #16 未结），需按舵机型号确认。
- **编造/不合格**：不提矛盾，直接断言其中一个。
- **核验**：`grep -rn "0x2E" corpus/scallion/`

### Q7　偏移量命令 0x27 和 0x28 有什么区别？

- **考察点**：两个相邻命令码的功能辨别。
- **期望**：`0x27` = `CMD_OFFSET_ADJUST`，**增量式**调整（加/减**不清零**）；
  `0x28` = `CMD_OFFSET_RESET`，**清零**。
  加分：指出 0x27 多次下发会**累积**偏移量，导致速度逐渐偏离设定值（CASE-002）。
- **编造**：把 0x28 说成别的功能，或说 0x27 每次会重置。
- **核验**：`上位机通信协议.md:221-222`、`串口命令汇总表.md:71-72`

### Q8　打包流程完整走一遍要经过哪些状态？

- **考察点**：完整性 + **不编造状态名**。9 个状态，漏一两个正常，编一个就是幻觉。
- **期望**（`流程汇报_20260423.md:169-179`，分区 F 状态机）：
  `PROC_NEW_IDLE` → `PROC_NEW_BELT_RUN` → `PROC_NEW_CUT_RUN` →
  `PROC_NEW_PACK_IMPELLER` → `PROC_NEW_PACK_M4` → `PROC_NEW_PACK_ROD_ON_1` →
  `PROC_NEW_PACK_ROD_OFF` → `PROC_NEW_PACK_ROD_ON_2` → `PROC_NEW_PACK_STOP`
- **编造**：出现形如 `PROC_NEW_PACK_DONE` / `PROC_NEW_WEIGHING` 这类
  **语料里不存在的状态名**。
- **核验**：`grep -n "PROC_NEW_" corpus/scallion/流程汇报_20260423.md`，
  把模型列出的每个状态名逐个对一遍。

### Q9　膜杆第二节不动作的根因是什么？

- **考察点**：这是本项目的"标准题"，第 3 层复测已实测过一轮。
- **期望**（CASE-001）：旧的 `g_pack_test_state` 状态机里 `g_pack_test_seg_ms`
  只记录**当前阶段**时间，缺乏全流程统一计时；膜杆分两节运行的逻辑与打包阶段
  总时间 `PACK_TEST_IMPELLER_DURATION_MS` 的判断**存在时序冲突**；
  分区 D/E/H 冗余，状态流转不清晰。
- **编造**：归结为"舵机坏了""接线松动""供电不足"等硬件原因 ——
  文档明确说的是**软件状态机**问题。
- **核验**：`grep -n "CASE-001" -A5 cases_seed.json`；`流程汇报_20260423.md` 3.1 节

### Q10　冰箱不制冷怎么修？〔库外题〕

- **考察点**：**它该不该说"我不知道"。** 这是全清单里最重要的一题。
- **期望**：明确说明知识库里**没有**冰箱相关文档，无法回答。
- **判定**：只要它开始给「检查压缩机 / 制冷剂泄漏 / 温控器」这类通用建议，
  **并声称来自文档或附上来源**，就是**带引用的幻觉** —— 比没有引用更危险，
  因为引用本身就是可信度信号。
  如果它给了通用建议但**明确声明这些不来自本知识库**，可以接受。
- **核验**：`grep -rn "冰箱\|制冷" corpus/` 应为 0 命中（已实测）。

#### 想自己加库外题？用这个方法，别凭感觉挑

**不要凭直觉判断"这个文档里应该没有"** —— 第 0 节的教训就是直觉不可靠。
按下面的步骤构造，保证出题前先验证过：

```bash
# 1. 候选问题先分词，看多字词在语料里是否有命中
python -c "
import sys; sys.path.insert(0,'.')
from retrieval.hybrid import HybridRetriever
from retrieval.tokenizer import tokenize_query
r = HybridRetriever.load('index')
for q in ['咖啡机不出水怎么办', '钢琴走音怎么调']:
    hits = [t for t in tokenize_query(q) if len(t) > 1 and r.bm25.search([t], top_k=1)]
    print(('有重叠' if hits else '零重叠'), q, hits)
"
```

- **零重叠** → 干净的库外题，门控应该拦下。
- **有重叠** → 概念虽不在库里，但用词撞上了（如"打印机卡纸"撞上库里的 3D 打印机项目）。
  这类题**门控按设计不拦**，正是最危险的场景，值得单独留着测。

`eval/dataset.py` 里已按这个标准分好了两组：`GATE_OFF_DOMAIN`（10 条零重叠）
和 `GATE_OVERLAP`（4 条有重叠），可直接取用。

## 4. 怎么解读结果

**这份清单不是通过/不通过测试。** 十道题全对不能证明系统可靠 ——
它只说明这十个具体场景没问题。它的真正用途是：

1. **发现失效模式**，然后回到检索层或提示层去修（比如 Q4/Q6 全都不指出冲突，
   说明系统提示里缺了「文档冲突要显式指出」这一条）。
2. **回归对比**：改动检索逻辑或提示词后重跑，看判定有没有变。
   这也是它必须**逐条记录断言和出处**、而不是只打勾的原因 ——
   没有细节的对比表，改动后没法判断差异从哪来。
3. **发现新的陷阱题**：哪道题第一次问就骗过了你，把它补进第 2 节。

### 与检索层评估的分工

| | 检索层（`report.md`） | 模型层（本清单） |
|---|---|---|
| 测什么 | 正确内容有没有被召回到 Top-5 | 模型有没有照着召回内容如实作答 |
| 方法 | 自动化，30 题 × 4 配置 | 人工，10 题逐条核验断言 |
| 能测出 | 召回率、排序质量、门控误杀 | 编造、张冠李戴、不承认不知道 |
| **测不出** | 模型拿到正确块后答错 | 召回缺失（模型没材料，只能编或说不知道） |

**两层都测不到的是「检索给了部分相关的块、模型据此推出了错误结论」** ——
这正是本项目最初的动机（见 README），也是这份清单第 2 节里
Q4、Q6 两道**冲突题**专门要逼近的场景：语料里有相关内容，但**互相矛盾**，
模型是老实指出矛盾，还是挑一个说得言之凿凿。
